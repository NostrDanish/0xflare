# Security Audit — 0xflare — 2026-10-21 (re-run)

## Summary

Re-run of the 2026-10-20 audit. Privacy-hardened nosflare derivative: DM/general/payment Worker relay profiles + Tor-hidden strfry ghost variant. **No code changes since the previous audit** (HEAD still a74cf83, 2026-07-17). The HIGH finding was re-verified by reading `profiles/dm/src/index.ts` in full today: once any client completes NIP-42 auth (with ANY key), `handleReq()` returns up to 200 newest stored kind-4/1059 events matching the filter with **no scoping to the authenticated pubkey** — a privacy-defeating read path for a relay whose purpose is DM confidentiality. `newChallenge()` still uses `Math.random()` + timestamp for NIP-42 challenges.

Findings: 0 Critical / 1 High / 2 Medium / 2 Low (unchanged from 2026-10-20)

## Delta vs 2026-10-20

- HEAD unchanged (a74cf83); no commits since 2026-07-17.
- FLR-01 re-verified today: `handleReq()` selects all events `ORDER BY created_at DESC LIMIT 200` and matches filters without author/p-tag restriction to `_authed`.
- FLR-02 re-verified: `newChallenge()` = SHA-256 of `Math.random() + Date.now()`.
