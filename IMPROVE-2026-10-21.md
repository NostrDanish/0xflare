# Improvement Deep-Dive — 0xflare — 2026-10-21

Scope: main (`profiles/dm`, `profiles/payment`, `profiles/general` listings, `ghost/`). Sources read: `README.md`, `profiles/dm/README.md` + `src/index.ts` (full), `profiles/payment/README.md` + `src/index.ts` (full) + `src/cashu.ts` (full), `profiles/payment/package.json`.

## Top recommendations (ranked, with effort S/M/L)

1. **DM Vault REQ scoping fix — the vault currently isn't a vault (M).** In `profiles/dm/src/index.ts`, `handleReq` runs `SELECT ... ORDER BY created_at DESC LIMIT 200` for **any** authenticated pubkey and filters in JS with `matchFilter` — which ignores `#p` tags entirely (dead code `if (f.limit && false)` too). Net effect: any authenticated user can REQ and receive **everyone's stored DMs** (ciphertext, but the whole point of the vault is compartmentalization; metadata + ciphertext mass-collection is the threat). Design:
   - After NIP-42 auth, rewrite every REQ server-side: force `WHERE pubkey = ? OR id IN (SELECT event_id FROM tags WHERE tag='p' AND value=?)` bound to the authed pubkey. Reject filters that can't be scoped with `CLOSED: "restricted: vault serves only your own DMs"`.
   - Implement real `#p` matching (normalize tags into a `tags(event_id, tag, value)` table with index, or `json_each` in the interim).
   - Same fix needed in `profiles/payment/src/index.ts` (identical handleReq) — it stores 9734/9735 zaps, also user-scoped data.
2. **Fix or remove `broadcast()` before it becomes a leak (S).** `broadcast(ev)` sends every new event to all sessions under subId `"broadcast"`. It's currently inert only because `this.sessions` is never populated (hibernation-style `acceptWebSocket` without tracking). The moment someone "fixes" session tracking, the vault live-streams all DMs to all connected users. Correct implementation: on EVENT, look up sender + `p`-tag recipients, find hibernated sockets via `state.getWebSockets()` + attachment pubkey, and deliver only to matching subscriptions. Do this together with #1.
3. **Cashu/LN admission hardening — required before real money (M).** (`profiles/payment/src/cashu.ts`, `index.ts`):
   - `validateProofs` doesn't enforce `Number.isInteger(p.amount) && p.amount > 0` — negative/fractional amounts can game the `total >= ADMISSION_SATS` check. Also verify each proof's `id` (keyset) belongs to `MINT_URL`'s advertised keysets and unit is `sat`.
   - `redeemAtMint` POSTs `/v1/swap` with `outputs: []` — confirm against your mint's NUT-03 semantics (some mints reject empty outputs; a rejected swap after the client revealed secrets = user funds at risk). Prefer `POST /v1/checkstate` (NUT-07) to verify unspent, then swap with a change output back to a relay-owned key, or use mint quote+melt flow. Add idempotency: hash proof secrets, store in D1 before redemption, single-flight per pubkey.
   - **Admission state is in-memory** (`cashuAdmitted`, `paidPubkeys` Sets) — lost on every DO eviction/hibernation; paying users get silently un-admitted. Persist to `state.storage` or D1 (`admissions(pubkey, method, ts)`).
   - LN path fails **open** when `PAYMENT_URL` is unset ("dev mode") — invert: fail closed unless `ALLOW_DEV=true` explicitly set. `checkPaid` also caches on any `r.ok` without checking the paywall response body.
   - NIP-42 challenge = `sha256(Math.random()+Date.now())` — predictable; use `crypto.getRandomValues` (32 bytes). Also persist auth across hibernation via `serializeAttachment` (as upstream nosflare v7 does); today `_authed` on the socket vanishes on hibernate, forcing re-auth loops.
4. **Shared-core extraction (M).** `profiles/{dm,general,payment}/src/index.ts` are three drifting copies (dm has the `f.limit && false` dead branch, payment added CASHU, general unknown). Extract `packages/relay-core` with profile configs; fixes like #1 then land once.

## Missing gates (CI/tests/protection)

- No `.github/`, no tests, no typecheck script in any profile. A relay holding DMs and taking payment with zero CI: add at minimum `tsc --noEmit` + esbuild build + a small protocol test (auth round-trip, scoping REQ, cashu admission with a mock mint). Add gitleaks (`.dev.vars.example` exists — real `.dev.vars` is one bad commit away).

## Quick wins (code/config)

- `initDb()` runs on every EVENT/REQ — run once at DO construction (or use D1 migrations like nosflare's worker).
- Rate limiter buckets keyed by authed pubkey are good; but `rateOK` Maps are unbounded — cap + LRU.
- `handleReq` `LIMIT 200` with no time ordering guarantee per filter — apply filter `since/until/limit` in SQL.
- `ghost/`: pin the strfry docker image by digest (not tag) and add a healthcheck; tor + nginx configs unreviewed this pass.

## Ecosystem alignment notes

- NIP-17 (1059) + NIP-04 (4) only is the right minimal DM surface; with scoping fixed, advertise `auth_required: true` in NIP-11 (limitation block) so clients pre-auth.
- Cashu admission is a differentiator (no LN payment-graph correlation) — after hardening, document the exact NUT flow in the profile README so users can reproduce with any mint.
- Workers limits verified: 128 MB isolate, DO SQLite 10 GB — 4 GB prune target for dm is conservative and fine.
